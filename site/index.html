    A proof you can check, not a promise.

    Every fix ships with a signed Access Safety Passport. It is tied to the exact commit, and it goes stale the moment the code changes.

    Bound to the commit

    The passport records the fix commit, its tree and the hash of the diff. Change one line afterwards and the proof no longer matches.

    Signed

    An Ed25519 signature covers the whole passport. Edit a number in the claim and verification fails, with no secret needed to check it.

    Attacked before it is trusted

    The Patch Court breaks every new guard three ways: switched off, inverted, and blocking everyone. A guard that changes nothing gets flagged.

    Built to be safe to run.

    Every patch faces the same deterministic checks, and the tool is contained by design. An AI cannot talk its way past either.

    Contained

    • Sandbox onlyA copy of your app runs on localhost. Requests to any other host are refused, including from the browser.
    • Fake data and test accountsNever point it at production or real credentials.
    • Nothing leaves your machineYour code and your model key stay local. Gatewise has no model inside.

    Constrained

    • One bug classObject-level authorization only, where one account reaches another account's data.
    • Guard-only patchesNo removed or renamed functions, no new dependencies, one file, and a cap of 20 changed lines.
    • A deterministic judgeSeven fixed rules: the leak reproduces first, the diff applies, only leaking cells change, normal responses stay identical and the app's own tests pass. The verifier is tested with a do-nothing patch and a block-everyone patch.

    Accountable

    • Evidence for every claimScreenshots, the verdict per patch and a note on what was tested and what was not.
    • A person mergesThe pull request is ready to merge, and only a human presses the button.

    Questions a skeptic would ask.
    
    
    
      
    Does Gatewise need an API key, or send my code anywhere?
    No. Gatewise has no model inside. Your AI client brings its own, and your code stays on your machine. The sandbox runs on localhost.
    
      
    Will it touch my production site?
    Never. It tests a throwaway copy with fake data and refuses any host that is not localhost, including from the browser.
    
      
    What if my AI's fix breaks something?
    The verifier retests every account against every item. If a patch would lock anyone out, it is rejected and names exactly who, so your AI can retry.
    
      
    How do I know the proof is still true?
    Run python -m gatewise.cli verify-passport gatewise-report/passport.json --repo .. It reports VALID, STALE if any code changed after the proof, or TAMPERED if the passport itself was edited.
    
      
    Does it merge for me?
    Never. It opens a pull request and gives you the link. A person reviews it and presses Merge.
    
      
    Can my team run it in CI?
    Yes. python -m gatewise.cli scan --fail-on-leak builds the sandbox from a commit and fails the job when a leak is proven.
    
      
    What does it not do?
    It tests one bug class, object-level authorization. Automatic patching supports Python and FastAPI apps today. A passing run means the flaw is fixed for the tested accounts, items and endpoints. It does not prove nothing else is wrong.
    
      
    Who built this?
    It was built for the Hack on Track hackathon, problem statement 1, The Verified Fix.
